## 默认产品决策

| 项目 | 行为 |
| --- | --- |
| 访客 | 浏览公共书单、作品和活动；写操作返回 401，界面转到登录，保留站内返回地址。 |
| 登录名 | 3–32 位 ASCII 字母、数字、下划线，统一小写且唯一；注册后不改。 |
| 昵称（display_name） | 1–40 字，允许重复，可修改，拒绝控制字符；前台导航、推荐者名单、理由和消息只显示昵称。登录名在本人账户设置和管理员治理界面保留，注册与登录仍使用唯一登录名。 |
| 身份含义 | 真实可登录账户及稳定归属；未核验实名、邮箱、手机号或“一个自然人只能一号”。 |
| 密码 | Django 默认 PBKDF2，至少 12 位，拒绝常见和纯数字密码，输入最多 1024 字符。 |
| 会话 | 256 位随机令牌，库中只存 SHA-256 摘要；HttpOnly、SameSite=Lax，生产环境 Secure；30 天固定有效期。 |
| 安全 | 所有写请求通过 CSRF/同源检查；注册、登录、改密及贡献写入分别限流；成功登录轮换当前浏览器会话和 CSRF。 |
| 多设备 | 同账户多个有效会话使用同一贡献身份；退出仅撤销当前会话；改密、运维重置、管理员停用撤销全部会话。 |
| 找回密码 | 无邮件/短信依赖；仅运维交互命令 `reset_account_password`。运维应线下核实身份，系统不凭匿名历史推断账户归属。 |
| 管理员 | 既有 Admin/AdminSession 独立保存，不是普通读者；管理端登录不自动获得普通账户身份。需要参与推荐时另登录读者账户。 |

管理员可在 `/manage/readers/` 按登录名或展示名检索、停用和恢复读者。操作必须提供原因，审计只记录账户状态，不记录密码或令牌。恢复后需重新登录。停用阻止账户写入和接收新通知，原贡献和既有消息保留，不默认撤销作品推荐；异常贡献仍使用已有治理入口逐项处理。

## 身份与已有模型联动

迁移 `0011_accounts_and_notifications` 增加 `Account`、`AccountSession`、`WorkLikeEvent` 和 `Notification`，不修改、重写或猜测归属既有贡献。

每个账户在注册事务中创建专属 `AnonymousClient` 记录作为内部贡献主体（字段名保留以兼容既有业务），并以 OneToOne 唯一关联。它的随机令牌不发给浏览器，旧 Cookie 不绑定账户。只有有效账户会话可解析到这个主体。该主体保留很长的内部有效期，实际认证始终受账户会话 30 天有效期、状态和版本校验控制，不能凭旧匿名 Cookie 访问。

如此可保留推荐/点赞唯一约束、理由归属、手工作品资料所有权、标签来源、幂等记录、管理员审计、合并及撤销保护。清除 Cookie 后重新登录可恢复贡献权限，不会生成新贡献主体。注册前或历史匿名贡献只显示“历史匿名推荐者”，没有自动认领入口，也不补发历史通知。

`BOOKLIST_LEGACY_TESTS=1` 仅在 `BOOKLIST_ENV=test` 时允许旧匿名测试夹具通过原路径，方便原有 304 项业务回归；development/production 不允许该开关关闭账户要求。新增账户测试显式开启 `REQUIRE_ACCOUNT=True`，即使整套回归启用了兼容夹具，也仍验证身份版权限。

## 推荐与展示

- 公共推荐与每期活动独立统计；参与活动同时创建公共推荐，同账户不重复计数。撤回活动推荐不撤回公共推荐。
- `+1` 加入该范围的共同推荐，不是点赞；理由可选且与推荐关系分离。
- 每轮最早的非失效推荐为“首次推荐”。其撤回时保留展示并标记“已撤回”，但不再计数；共同推荐者只列出当前有效成员。首次推荐者重新加入不成为自己的共同推荐者。
- 推荐数归零，仍按原规则归档本轮理由和点赞，下一轮重新确定首次推荐者。手工作品重填及结束活动的书目快照规则保持。
- 首次推荐者和共同推荐者仅在作品详情页展示，公共与活动书单的作品卡片不展示名单；详情页实时更新。理由详情显示作者展示名与唯一登录名。展示名使用当前账户资料，不是历史实名快照。
- 实时刷新保留共同推荐名单的展开状态，不改变推荐、点赞的独立按钮与计数。

合并按既有贡献主体去重，撤销仍受原 ChangeEvent 和逐行快照保护。通知事件留在原作品以允许安全撤销；生成新通知前检查当前合并作品族，防止把合并当作刷新通知限制的方法。消息中的作品入口检查当前登录收件人并解析合并后的作品，作品治理可见性仍优先。

## 通知语义

| 事件 | 收件人与规则 |
| --- | --- |
| 公共作品从未赞到已赞 | 当时公共范围有效推荐者的有效账户。 |
| 活动作品从未赞到已赞 | 当时该活动有效推荐者的有效账户；不额外发公共范围消息。 |
| 赞自己的推荐作品 | 可按原产品规则计入点赞，但不通知自己；仍通知其他有效推荐者。 |
| 重试同一次请求 | 使用原幂等记录返回，不重复通知。 |
| 撤赞后再赞 | 点赞状态可恢复，但同账户/作品/范围的永久事件账本阻止再次通知。 |
| 退榜后重新入榜 | 点赞计数按原规则新一轮统计；通知去重不清零。 |
| 之后加入推荐 | 不补收已发生的点赞，也不因旧点赞再次启用而收到消息。 |
| 理由赞同 | 仍独立计数、撤销、排行；本版不产生通知，不冒充作品点赞。 |

作品点赞、事件账本、消息在原贡献写事务中共同提交或回滚。每个事件与收件人有数据库唯一约束。永久账本即便没有收件人也保留；它表示该账户已经触发过该范围作品点赞事件，而不是“发送失败等待重发”。

消息列表按 id 倒序，每页 50 条。提供单条/批量已读（最多 100 个正整数）及全部已读，仅更新当前收件人的消息，重复操作幂等，不返回其他账户数据。导航显示未读总数，约 30 秒刷新，隐藏页面暂停、错误退避、会话失效停止。通知保留事件时作品标题/活动标题和发生时间，不因撤赞删除；点赞者展示名取当前资料。
