# 采集入库期间的只读访问

2026-10-20 本地日志中，16:53 左右出现详情与轮询 503，时间与第 52 批本地验收入库重合，入库完成后恢复。旧异常处理没有记录 SQLite 具体错误，因此不能仅由历史 JSON 证明每次都是锁超时；代码中确认存在浏览请求争用业务库写锁的路径，并通过独立连接持有 BEGIN IMMEDIATE 的回归用例验证修复。

## 调整

- catalog_read、catalog_search 的限流计数写入数据目录下 read_rate_limits.sqlite3，使用持久化 SQLite 原子计数，多进程共享；不改动身份、登录、写接口的原有限流。
- 没有需要到期转换的活动时，advance_due 只做读取；实际转换仍进入原子事务并重新查询。
- 网页 GET 遇到数据库异常返回带重新加载入口的 HTML 503，API 保留 database_unavailable JSON；响应不可缓存并包含 Retry-After。
- 身份中间件异常使用相同错误响应；日志记录请求路径、SQLite 错误分类和原因，不记录 Cookie、密码或请求正文。

没有修改采集队列、来源校验、审核规则或导入脚本，也没有靠提高业务库等待时间来隐藏问题。独立限流存储失败时仍拒绝请求。

## 验证

独立连接持有作品库写锁期间，公共书单、公共/活动详情、活动书单、公共/活动统计均可正常读取。额外检查并发限流不超额、到期转换仍在事务中，以及网页/API异常格式。
