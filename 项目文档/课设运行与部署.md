# 课设分支运行与部署

课设分支 `codex/course-project-upgrade` 的业务范围见《课设升级设计与验收基线》。已确认部署域名为 `course.sharedbooklist.xyz`。线上的 DNS、证书和入口切换需等待方案会话独立验收及放行。

## Windows 本地验收

在课设 worktree 根目录执行。Python 3.14 与 SQLite 版本要求沿用项目 README。以下假设本工作树已创建虚拟环境，或将 Python 路径替换为已验明的运行时。

```powershell
$env:BOOKLIST_ENV = 'development'
$env:BOOKLIST_DATA_DIR = Join-Path (Get-Location) '.runtime/course-demo'
$env:BOOKLIST_ALLOWED_HOSTS = 'localhost,127.0.0.1'
$env:BOOKLIST_QQ_EMAIL_LOGIN = '0'
$env:PYTHONIOENCODING = 'utf-8'
& .\.venv\Scripts\python.exe -B manage.py migrate --noinput
& .\.venv\Scripts\python.exe -B manage.py seed_identity_demo
& .\.venv\Scripts\python.exe -B scripts/course_search_benchmark.py
& .\.venv\Scripts\python.exe -B manage.py runserver 127.0.0.1:8913 --noreload
```

合成演示命令只在空开发库运行一次。它写出 `.runtime/course-demo/preview-credentials.json`，包含随机生成的三个读者和后台管理员凭据。该文件只有本机使用，不提交。两个读者通过账户设置查看读者编号，策展负责人用编号邀请。手机验收可在受控浏览器中使用窄屏视口，同一 HTTPS 域名下的多人测试使用独立浏览器会话。验证路由从首页进入，阅读路线位于任一演示作品详情。

固定题集使用 4 条有答案查询和 1 条无答案查询，分别记录 AI找书整句关键词检索、预先约定的公共书架关键词与标签操作，以及模型意图在可见目录中检索的前三结果。默认使用模拟意图，仅验证检索链路。仅在配置独立密钥及明确授权实际调用后，加 `--live` 联调，并将回退次数与真实解析结果分开。已接通的服务端变量为 `COURSE_DEEPSEEK_KEY`、`COURSE_DEEPSEEK_MODEL`、`COURSE_DEEPSEEK_DAILY_CALLS`。调用默认每日 30 次，单 IP 每小时 6 次，每进程只允许一条在途请求，输出上限 384 tokens，套接字超时 5 秒，不自动重试。日志只记录回退异常类型。

## 独立站部署准备

使用新的检出路径 `/opt/shared-booklist-course`、Compose 项目 `shared-booklist-course`、应用配置目录 `/etc/shared-booklist-course`。新站只绑定 `127.0.0.1:8908`，由独立的公网 vhost 终止 HTTPS。Compose 管理专用的 `course_data` 与 `course_backups` 卷，静态文件从同一版本的镜像生成。应用、管理和 CSRF cookie 使用 `course_booklist_*` 名称与 host-only 范围。容器应用使用自己的出网网络；端口、网络网段、磁盘和部署提交先在目标主机核对。

1. 用独立的新密钥填写 `/etc/shared-booklist-course/app.env`，权限 0600。模板在 `deploy/course.env.example`。联系邮箱和公开备案信息按新站实际情况填写。独立 `ai.env` 可缺省。启用 QQ 邮箱验证码时，可在同目录创建权限为 0600 的 `mail.env`，设置 `BOOKLIST_QQ_EMAIL_LOGIN=1`、`BOOKLIST_SMTP_USER` 和 `BOOKLIST_SMTP_PASSWORD`，并验证实际送达。只有应用容器读取这个可选文件，顺序为 `app.env`、`ai.env`、`mail.env`，同名变量以最后读取的值为准。缺省时使用已有环境配置，演示可使用账号密码注册和登录。
2. 设置 `COURSE_RELEASE` 为审核通过的完整提交（容器标签），在课设检出运行 `docker compose -f deploy/course.compose.yml config --quiet` 和 `docker compose -f deploy/course.compose.yml build`。
3. 空卷首次运行 `docker compose -f deploy/course.compose.yml run --rm --no-deps app python manage.py migrate --noinput`。已运行的新站升级前先在其备份卷验证可恢复的数据库备份。新站目录和数据卷与正式身份版分离。
4. 私网动态地址池使用 `172.30.31.8/29`，固定保留 `.1` 给网桥、`.2` 给课设 gateway。若曾用旧配置启动课设栈，先核对 `docker network inspect shared-booklist-course_course_private` 的 `IPAM.Config`。缺少 `IPRange` 时，在课设工作目录用原启动所用的课设 Compose 文件组合执行 `down`（保留卷，不加 `-v`），让下一次启动创建带新地址池的私网。执行 `docker compose -f deploy/course.compose.yml up -d --wait`。从本机读取 `curl --fail -H 'Host: course.sharedbooklist.xyz' http://127.0.0.1:8908/health/`，同时核对网关静态资源、SQLite 备份服务、账号注册/登录，以及四项入口。默认生产库从空白迁移开始，可使用新建账号添加合成记录。
5. 放行后为该子域添加 DNS 并签发独立证书。以 `deploy/course-host.nginx.example` 为参考，按目标主机实际公网入口部署单独的 vhost，先进行对应网关的配置检查。公网核验覆盖 TLS、三项社群入口、作品详情、身份版原入口和旧匿名域名跳转。不要从 host-only cookie 迁移读者账号。
6. 撤回公网只移除新站 vhost 或新子域记录。需要停新站时运行 `docker compose -f deploy/course.compose.yml stop`，保留数据及备份卷。不要执行 `down -v`。

### 核对自动备份

应用与调度器使用同一课设 SQLite 数据卷。备份进程用 `mode=ro` 打开源数据库，并通过 SQLite 在线备份 API、完整性检查和隔离恢复演练生成回执。课设数据卷以可写形式挂载给备份进程，允许 SQLite 在冷启动或连接切换时创建、更新同目录下的 WAL 和共享内存文件。备份容器根文件系统保持只读，备份成品写入单独的备份卷。

栈启动后，使用相同的课设 Compose 文件组合执行：

```bash
docker compose -f deploy/course.compose.yml exec -T backup cat /backups/backup-health.json
```

确认 `checked_at` 对应此次冷启动、`status` 为 `verified`、`backup.restore_drill` 为 `true`，并核对对应的 `.sqlite3` 与 `.verified.json` 文件。若为 `needs_attention`，记录 `phase`、`error_type` 以及回执中可用的 `sqlite_errorcode` 和 `sqlite_errorname`，再查课设备份容器日志。手工执行一次备份的结果应单独记录，冷启动检查以自动进程的回执为准。

## 现网公网入口为 Docker 容器时

现有公网代理在容器里，其回环地址属于容器自身。应使用以下接入方式。宿主 Nginx 示例仅用于实际由宿主 Nginx 提供公网入口的环境。以下操作由负责 DNS 和服务器接入的运营者在独立验收放行后执行。

1. 确认两段课设网段 `172.30.31.0/28`、`172.30.32.0/28` 与服务器路由和各 Docker 网络均不重叠。按实际检查结果处理冲突，不能随意只改一处 IP。创建单独内部桥接网络：`docker network create --driver bridge --internal --subnet 172.30.32.0/28 --gateway 172.30.32.1 --ip-range 172.30.32.8/29 shared-booklist-course_edge`。动态地址限定在 `.8/29`，为课设 gateway 和公网代理分别留出 `.2` 和 `.3`。该边缘网络由运营者创建，Compose 不会更新其地址池。若网络已存在，先用 `docker network inspect shared-booklist-course_edge` 核对 `IPAM.Config`。需要重建时，先按第 6 步撤回课设接入并确认该网络无连接容器，再重建这个课设网络。
2. 迁移和启动课设应用时追加 `-f deploy/course.container-edge.compose.yml`。只有课设 gateway 接入该桥，地址为 `172.30.32.2`。应用和数据库不加入公网代理所在网络。gateway 的 8081 未发布到宿主，只受理来自 `172.30.32.3` 的课设域名请求；8080 保留本机健康检查。
3. 备份并记录现网公网代理的 Compose 完整命令、渲染前配置与现有证书挂载。确保公网站点可在新域签证之前处理挑战，或使用由运营者掌控的 DNS 验证方式签发课设专用证书。把证书放在 `/etc/shared-booklist-course/tls`，让现网代理运行用户只读访问。
4. 以 `deploy/course-public-vhost.conf.example` 生成课设独立 vhost 并安装到 `/etc/shared-booklist-course/public-vhost.conf`。在现有 Nginx 的 `http {}` 内新增 `include /etc/nginx/course-vhost.conf;`，放在最后一个右花括号前。现网各 server 块、静态目录和证书保持原值。现网代理的 Compose 命令末尾叠加 `deploy/course-public-edge.compose.example.yml` 的受控副本，以 `172.30.32.3` 接入课设边缘网络，并挂载新站证书与 vhost。合并后的 `docker compose … config --quiet` 通过后，检查渲染配置仅多出预期网络及挂载。
5. 使用叠加后的 Compose 命令进行一次性代理语法检查，例如 `docker compose … run --rm --no-deps --entrypoint nginx proxy -t`。因为运行中的代理可能占用静态 IP，应使用隔离检查环境和相同文件挂载，或为检查容器使用临时网络地址。检查证书权限、Host、静态模块 MIME 类型。切换仅针对公网代理，记录维护窗口和实测短暂中断，并验证两个旧域名和课设域名。公网代理覆盖 `X-Course-Client-IP`，课程 gateway 仅信任校验过的来源并设置单跳 `X-Forwarded-For`，Django 仅信任课设内部 gateway `172.30.31.2`。
6. 撤回时移除课设 include、课设 vhost 叠加配置及现网代理的课设网络连接，使用原代理配置核验并恢复。可撤掉 course DNS，必要时仅停止 course Compose 服务。课设数据、备份和证书留存供检查；不修改现网应用、证书和数据库。

本机 Windows 开发预览、Compose 静态校验、Docker/Linux 实际启动和公网访问是独立验证项。实际 DNS、TLS、新站公网可达、密码或邮件登录可用性，以部署后的观察为准。
