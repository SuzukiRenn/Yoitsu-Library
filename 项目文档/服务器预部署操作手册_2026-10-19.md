# 服务器预部署操作手册

本阶段仅预部署，不发布公网端口，不设置域名、DNS、TLS 证书或创建真实管理员密码。容器内 HTTP 健康检查不代表公网 HTTPS 验收。不上载本地开发/测试数据库，不自动导入示例作品。

## 已核实环境与方案

服务器只读检查确认 Ubuntu 24.04 / x86_64，系统 Python 3.12.3、SQLite 3.45.1，不满足项目运行时。Docker 和 Compose 可用，固定镜像及依赖站已完成实际下载和构建验证，但访问速度波动明显。本地检查输出位于 `.runtime/server_predeploy/preflight.json`，不进入 Git。

独立容器使用[官方 Python 镜像](https://hub.docker.com/_/python)，固定 Python 3.14.8 的 Linux amd64 镜像摘要。SQLite 3.53.2 的源代码按[官方发布记录](https://www2.sqlite.org/releaselog/3_53_2.html)核验 sqlite3.c 的 SHA3-256，下载归档固定 SHA-256；编译库仅放入容器，不替换系统 Python/SQLite。Linux lxml 与 [Gunicorn](https://pypi.org/project/gunicorn/26.2.0/) 及原运行依赖全部锁定 wheel 哈希。SQLite 源码与 Python 基镜像校验值写在 `deploy/Dockerfile`，依赖在 `requirements/production-linux-amd64-cp314.lock`。

应用、活动调度、备份分为三个容器，不映射主机端口，使用内部网络。应用一进程两线程，活动每 30 秒补处理一次，过期会话/限流/幂等记录每天清理。SQLite 每 6 小时做备份及独立恢复演练；首次运行也立即验证。备份不自动清理，需在后续运营中设置保留策略及磁盘监控。容器日志滚动，Gunicorn 不记录请求 URL。

## 路径与保密

| 用途 | 服务器路径 |
|---|---|
| 代码发布 | `/opt/shared-booklist/releases/<完整提交号>` |
| 当前已验收版本 | `/opt/shared-booklist/current` |
| 部署互斥锁 | `/opt/shared-booklist/deploy.lock` |
| 随机生产配置 | `/etc/shared-booklist/predeploy.env` |
| 配置备份 | `/etc/shared-booklist/backups/`，root 私有 |
| 独立数据库 | `/var/lib/shared-booklist/predeploy/data/booklist.sqlite3` |
| 数据备份 | `/var/lib/shared-booklist/predeploy/backups/` |

配置首次生成后不覆盖，真实密钥只在服务器 root 私有配置中。应用以 UID/GID 10001 运行，代码只读，数据挂载可写，移除容器 capabilities，不允许新增权限。备份连接使用只读 SQLite 模式，但挂载目录仍需可写，以维护 WAL/SHM；备份不是拷贝单个运行中的主数据库文件。

密码登录使用已确认主机密钥的本机 SSH，密码只在本机终端输入。服务器地址、密码、私钥、配置、镜像归档、数据库与实际执行日志不进 Git。

## 执行

先在项目 PowerShell 中运行只读检查；将参数中的占位符换为自己的地址，不将地址写回脚本：

```powershell
powershell -NoProfile -File .\scripts\server_preflight.ps1 -ServerHost 服务器地址
```

代码推送完成后，使用已审查的本机当前 HEAD 完整 40 位提交号运行：

```powershell
powershell -NoProfile -File .\scripts\predeploy.ps1 -ServerHost 服务器地址 -Release 完整提交号
```

PowerShell 封装将当前已提交版本及其 Git 历史生成 bundle，通过同一次 SSH 连接传送，不打包工作目录、未提交文件或运行数据。服务端取得部署锁后校验传送 SHA-256、Git bundle 完整性和导入提交号；不依赖服务器连接 GitHub。直接执行未封装的 Bash 脚本仍保留从 GitHub 拉取的方式。一次服务器拉取尝试因 120 秒超时退出，未进入镜像构建或数据库操作。

按顺序检查 Docker 引擎、空间、部署锁，导入固定提交，构建运行镜像和独立验证镜像，在不挂载业务数据的容器内执行完整 Django 回归与备份测试。固定摘要的基镜像已存在时直接使用，否则拉取。验证镜像的 Node.js 工具层独立于应用源码，复制同一固定基镜像构建的运行版本 Python、安装包、SQLite 库和应用，避免仅源码变更就失效工具安装缓存；Node.js 不加入运行镜像。回归前输出实际 Python、SQLite、lxml、libxml2 和 Node 版本。然后生成或沿用配置，通过生产安全检查，再停止本项目写入、备份旧库、迁移、启动服务和健康检查、再次备份及恢复演练，最后切换当前代码指针。

成功必须出现 `PREDEPLOY_SUCCESS <提交号>`。拉取、构建和回归失败发生在停写前，不切换旧版本；停写后失败则停止本项目容器并保留数据。不会自动在未知新 schema 上回退旧代码，也不会自动恢复旧备份覆盖后续贡献。远程标准输出和错误输出均写入本机 `.runtime/server_predeploy/` 日志；本机 SSH 连接诊断仍显示在终端。

首次服务器构建确认官方 Python 镜像和 SQLite 源码可下载，Debian 依赖下载持续有进展，但速度仅为每秒几十 KB。运行镜像构建时限调整为 2 小时、验证镜像为 1 小时；这是最大等待时间，不是预计耗时。未更换依赖源，也未跳过哈希校验或 Linux 测试。已经启动的旧脚本仍按原时限执行，修改只影响下一次运行。

本机 Ctrl+C 或 SSH 断开不保证远程子进程立即退出。再次部署会等锁最多 30 秒；仍被占用则输出持锁诊断并停止，不能通过删锁文件绕过。只读检查会报告原部署文件描述符的持有进程、进程状态、年龄、本项目容器和数据库是否存在；没有发现文件描述符持有者不单独视为锁已释放，应以实际取得锁为准。

生产配置检查明确允许唯一的 `security.W021` 提示：未加入 HSTS 预加载名单。这是有意保留的域名发布决策，不影响现有 Secure Cookie、HTTPS 重定向和 HSTS 配置；其他警告或错误阻止发布。
