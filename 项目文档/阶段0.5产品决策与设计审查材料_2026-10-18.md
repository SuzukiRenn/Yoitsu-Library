## 3. 有效性定义草案

“存在”“有效贡献”“可公开展示”分开；页面不显示文本不必然减少活动人数。下表已落实 D1/D3/D4/D6—D9；最终字段、索引和输入口径仍待阶段 1 设计，不直接视为冻结 schema。

| 对象 | 数据有效性方向 | 展示或权限附加条件 |
|---|---|---|
| 作品 | 正式根作品，无合并重定向或解析到有效根 | 隐藏、待核查不公开；公共收录与理由数分离（D3） |
| 公共理由 | 公共范围、合法身份、理由非空、未归档、未删除、未资格失效；空提交不建记录 | 文本未被隐藏且作品公开；文本隐藏不取消资格，理由清空不撤销作品收录 |
| 活动推荐 | 本期、合法身份、未撤回/归档/资格失效，作品已通过公开审核 | 空理由仍有效；文本隐藏不减人数，资格失效才影响计数；历史审计修正后按有效记录重算 |
| 点赞 | 对应范围、身份、当前有效、未归档/取消 | 新增活动赞须进行中、本期可见、有有效快照且未零贡献退出；作品隐藏不产生公开计数 |
| 标签来源关联 | 来源类型与操作者匹配、未按相应原因撤销/归档 | 来源抑制只影响该来源；作品级禁止覆盖全部来源，标签停用禁止选择/公开展示；展示按正式作品/标签去重 |
| 活动快照 | 本期正式作品唯一有效快照，未归档 | 零贡献退列表仍保留，须重新推荐返回；展示按本期有效贡献及隐藏规则，历史修正有提示 |

公共与活动有效唯一约束分开；不能依赖含 NULL activity_id 的单个组合唯一索引。来源标签、用户标签、管理员标签分别约束操作者；跨期关联需数据库可表达的约束与服务端事务复核。

## 4. 身份、导入与标签同步

身份流程：原始输入 → 本地标准名/已确认别名 → 规范化/模糊候选 → 必要时 AI 辅助 → 用户确认可信本地 ID → 提交时再次验证身份、隐藏、合并及版本。没有匹配允许原始标题作品，但同名不等于同作；可信同隐藏身份拒绝公开写入，未知身份仅同名则待核查、提示提交者，核查前不公开、不计活动推荐。公开审核状态与来源身份状态独立，不能靠选择已有候选绕过隐藏。

补绑来源 ID 若已占用，停止绑定并进入管理员合并预览；用户选中已有作品只决定当前请求，不能迁移历史贡献。同次请求用身份 + 范围 + 幂等键绑定请求摘要，同键异内容拒绝；具体保留时限与重试响应在阶段 1 定稿。

来源字段先校验获取状态，再应用显示优先级：管理员显式覆盖（包括允许字段主动空）→ 来源有效值 → 未匹配时原始输入。解析失败/未获取保留旧值，明确空值才按字段规则清空；标题最终非空。恢复同步取消覆盖状态，不能与主动清空共用一个空值含义。

标签顺序：解析来源身份 → 解析已确认合并映射 → 校验完整集合 → 应用来源撤销/管理员抑制 → 合并用户及管理员独立来源 → 按治理规则去重展示。完整集合失败时保留旧来源关联。管理员抑制不能被同步复活，用户撤销只影响自己的来源。映射禁止循环；来源 ID 不同但同名先保留并核查。

停用标签保留关联历史，但禁止新选择和公开展示；单条来源抑制不影响其他来源。作品级标签禁止是独立结构，写入与公开查询均检查，来源同步不能清除。理由治理另以文本状态、资格状态分开建模；管理员隐藏/恢复保留原文审计，用户编辑不解除治理。治理状态及审核、标签禁止的变化也纳入合并后的变更检测。

## 5. 合并与安全撤销冲突矩阵

| 情况 | 合并动作 | 撤销保护 |
|---|---|---|
| 不同可信文库8 ID | 拒绝；身份错误先独立审计修正 | 不能靠清空 ID 绕过 |
| 只有一方有来源 ID | 有 ID 方为主，管理员确认 | 保留双方原身份与原始提交 |
| 公共理由同人冲突 | 新更新时间胜，同时间人工 | 旧记录归档；后来清空不得复活 |
| 同期活动推荐同人冲突 | 更新较新者有效，另一条归档；同时间管理员选，未选整次停止 | 撤回/失效/编辑均检测，不能回放旧资格 |
| 双方字段覆盖不同 | 逐字段管理员选择，未选整次停止，原值留存 | 不覆盖后续管理或来源更新，也不解除治理 |
| 同范围同人点赞 | 只计一次、保留去重证据 | 后来取消不得由撤销复活 |
| 标签/别名重复 | 按来源操作者去重，保留原归属 | 检查撤销、抑制和映射变化 |
| 同期双快照 | 早创建胜，同时间小 ID | 不重写保留快照，历史受 D4 约束 |
| 任一作品隐藏 | 合并后保持隐藏 | 撤销不得解除新增治理限制 |
| 预览后有写入 | 拒绝旧版本，重做预览 | 检查与修改同事务，冲突整次停止 |
| 新贡献或后续合并 | 有证据才判归属、禁止循环 | 依赖先撤；归属有歧义拒绝，不部分恢复 |

从阶段 1 起所有可变实体保存单调版本或等效变更序列；推荐清空、取消点赞等物理删除保存墓碑/删除事件，至少含实体 ID、操作范围、归属证据、旧/新版本、事件类型和时间，不要求保留已删除理由正文。匿名 token 原文、密码和 API 密钥不得进入快照或审计。合并日志保存前后版本及迁移来源；后续新数据记录足以追溯其创建目标的证据，不凭创建时间猜归属。

具体采用“版本 + 删除墓碑 + 合并逐项快照”的结构建议，尚未定 DDL。所有业务写入口必须进入同一服务层产生变更记录；后台绕过服务直接编辑将破坏撤销能力，必须禁止或纳入同一机制。撤销比较版本、当前治理、归属、唯一性和依赖，在同一事务完成审计和恢复。

## 6. 已确认输入口径及技术待定稿项

D10 已确认。前端可用 `Array.from(text).length`，后端可用 Python `len(text)`，但必须先应用完全一致的换行/首尾空白规则；组合字符按多个码点计，不能混用 JavaScript `.length` 的 UTF-16 单元计数。JavaScript `trim()` 与 Python `strip()` 的字符集合不能未经核对就假定相同，阶段 1 须明确共享口径并以同一组样例测试。原始来源值与有效标准值分开，导入超长不静默截断。分页/请求体积上限、幂等有效期、Cookie 生命周期、管理员会话时长和限流阈值仍是阶段 1 实施协议待定项，不能从 D10 的数值推导。

技术建议：管理员服务端会话与公开匿名 Cookie 分离；匿名 token 服务端签发、库内哈希；所有 Cookie 写入做 CSRF/来源校验；权限取服务端身份；安全默认值在实现说明里明示。会话停用/改密失效、最后管理员并发保护、错误码、重试及限流响应需要实际验收，框架存在这些组件不代表自动符合规则。
