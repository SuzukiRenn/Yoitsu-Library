日期：2026-10-19（Asia/Shanghai）。依据：总规范 v1.6、已确认的 D1—D12，以及本轮先形成的《阶段1技术设计》。结论：**阶段 1 基础服务的本地验收门槛通过**，可以推进阶段 2 的离线小样本导入；不是全部网站功能完成或生产部署通过。

## 交付与实现边界

- 独立 `.venv`：Python 3.14.6 / SQLite 3.53.2；Django 5.2.18、asgiref 3.12.1、sqlparse 0.6.0、tzdata 2026.5。`requirements/runtime.lock` 固定版本与下载 wheel 的 SHA-256；实际从官方 PyPI 下载，再通过本地 wheel 离线 `--require-hashes --force-reinstall` 成功重装，`pip check` 通过。wheel 与环境留本地、不入 Git。
- `config/`、`booklist/`、`static/text.mjs`、`manage.py`、配置示例、启动说明、管理命令及测试。只新增基础网页和安全 API，没有公开推荐/点赞/活动/采集/合并写入接口。
- 三个可重复迁移：`0001_initial` 建核心与支撑表，`0002_integrity` 建历史及完整性触发器，`0003_source_completeness_and_activity_times` 补来源集合完整性与实际活动时间检查。SQLite 改表重建时，在同一迁移事务维护触发器集合。
- 作品资料/独立覆盖、来源诊断、别名、标签/来源映射/关联/禁止、匿名身份、推荐/赞/活动/快照、管理员/会话/审计、系统转换事件、合并操作/明细/依赖、ChangeEvent 和幂等/限流结构。物理模型多于总规范的逻辑表清单；支撑表不是额外产品功能。
- 管理员初始创建、登录/退出、同权账号创建、停用、本人改密、服务器端密码恢复；匿名身份签发、续期及重置。密码和 Cookie token 原文不落库；管理员与匿名 Cookie 独立。最后管理员保护在服务事务和数据库触发器两层实现。
- 公开审核与身份匹配、文本隐藏与推荐资格、单来源抑制与作品级标签禁止分别建模；字段覆盖可显式为空。ChangeEvent 以数据库触发器覆盖业务原生 SQL/批量更新/删除，保存墓碑及单调事件序列；不记录理由正文或凭据。安全合并/撤销服务仍待阶段 6，不因这些表存在就宣称已实现。

本轮工程参数：JSON 请求体 32 KiB、分页默认 20/最多 100、匿名 Cookie 365 天可续期、管理员会话绝对 12 小时、幂等 24 小时。限流范围与数值、共享空白字符集合、时间精度、配置要求详见技术设计；这些是公开的实现选择，不追认为用户另行确认的产品数字。

## Git、配置与审计注意

已初始化**本地** Git 仓库，未创建远程、commit 或 push。新增根级忽略；`git check-ignore` 已核对新/旧虚拟环境、SQLite、旧浏览器 profile、wheel 与运行目录。首次暂存只选择本阶段源码、锁文件及项目文档；完整历史 HTML/运行目录不自动纳入。旧采集原型及历史样本仍保留在本地，后续首次导入它们时须单独筛选去敏样本。私有仓库不能代替密钥及会话资料审查。

数据库审计和事件为追加记录，普通 SQL 更新/删除被拒绝；测试数据库清理专用地暂撤并重建触发器，生产 API 没有该开关。生产不支持以 `flush` 清库。持有完整数据库写权限的运维仍能修改 schema/移除触发器，本实现不是对服务器所有者的防篡改系统。

生产配置默认严格：缺秘密/明确主机/代码目录外持久目录即失败，Secure Cookie/HTTPS 强制启用。反向代理信任、域名、证书、WSGI、监控、磁盘与并发容量仍须服务器实测；本轮没有连接或更改服务器。基础服务启动说明见根 README，初始开发库没有自动设置公开默认管理员密码。
