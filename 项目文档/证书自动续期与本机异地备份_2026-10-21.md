## 证书续期

RAM 用户为 `booklist-cert-renew`，自定义策略 `BooklistCertificateDNS` 的内容见 `deploy/renewal-ram-policy.json`。阿里云权限限制到域名，不能直接限制到一条 TXT；脚本仅向固定域名添加 `_acme-challenge` TXT，清理时同时核对挑战哈希及自己创建的记录 ID。不授予账号管理或全域名写权限。密钥仅在终端隐藏输入，保存在服务器 `/etc/shared-booklist/renewal/credentials.json`，root 私有目录 0700、文件 0600，不进入命令参数、聊天或 Git。

`deploy/manage_renewal.py setup` 使用既有 Certbot 固定镜像，先执行 `reconfigure` 的 staging 续期演练。只有演练成功、TXT 清理完成、正式证书未被测试证书替换、证书与私钥匹配、Nginx 配置检查和平滑加载及实际服务证书检查通过后，才启用 `booklist-certificate.timer`。定时器每天检查两次，带随机延迟和错过执行补偿。生产证书、ACME 账户与验证状态分开保存。

状态：`/etc/shared-booklist/renewal/status.json`；执行日志：`journalctl -u booklist-certificate.service`；定时器：`systemctl list-timers booklist-certificate.timer`。`needs_attention` 不能当成功。续期出错保留原正在服务的证书；替换或加载失败时恢复旧文件并重新检查。`manual-renewal.before.conf` 保留原手动配置，便于人工排查。正式公网切换时需同步本轮最新管理脚本，并再次验证实际监听地址及续期发布链。

## 本机异地备份

`scripts/pull_server_backup.ps1` 默认保存至项目下的 `backups/server/`，受当前 Windows 用户与 SYSTEM 的专用 ACL 保护，并已在 Git 忽略范围内。归档包含真实数据库的一致性快照、封面及旁边元数据、当前应用源代码归档、运行环境配置、现有 TLS 证书私钥及正式 ACME 账户，以及已安装的续期管理配置。归档含敏感材料，不应发布或作为普通项目文件上传。

服务器专用 SSH 公钥使用 `restrict` 与固定命令：仅允许 `snapshot`、下载指定格式的备份文件、以及验证成功后的 `ack`；不能执行 shell、SFTP、PTY、隧道或代理转发。私钥仅保存在本机 `.runtime/operations_20261021/offsite_ed25519`，文件夹 ACL 同样受限。它不是日常服务器管理密钥。

传输前后验证整个归档的 SHA256；随后逐一核对归档成员清单、文件长度与 SHA256，并拒绝路径穿越、符号链接和重复成员。数据库只恢复到本机临时目录，执行完整性、外键、作品数量及逻辑内容比较，不启动恢复副本服务。仅在这些检查全部通过后写入 `.verified.json` 成功回执，再通知服务器删除对应的临时导出文件，控制服务器磁盘占用。失败不生成成功回执，也不删除源备份。保留所有本机历史备份，不自动删除。

`scripts/install_pc_backup_task.ps1` 创建 `SharedBooklistOffsiteBackup` Windows 任务：本机每天 09:00，以及该用户登录时运行，错过时在条件允许后补执行。只在该用户已登录且网络可用时执行；允许电池供电，单次最多 30 分钟，同一任务不重入。任务使用受限备份密钥，不保存 Windows 或 SSH 密码。

电脑关机、未登录或网络不可用时无法接收新异地备份。服务器原有每 6 小时的一致性备份继续运行，但同机备份不代替异地副本。若需要电脑关机期间也持续获得异地副本，后续应改用独立对象存储。定时任务执行记录、`scheduled-backup.log`、`pc-backup-status.json` 和每份 `.verified.json` 共同表示实际结果；不能仅凭任务已创建就声称备份成功。

## 恢复边界

恢复演练始终在隔离目录进行。真实灾难恢复时，先核验归档 SHA256 和成员清单，使用归档记录的应用版本，在新数据目录还原数据库和封面；配置与证书按原权限安装，检查服务后再切换。不要直接向正在服务的数据库或已有用户贡献写入恢复内容。Windows 专用连接密钥不属于服务器应用恢复的前提，新服务器的 SSH 管理入口由云控制台重新建立。

依据：[阿里云 DNS 自定义权限](https://www.alibabacloud.com/help/en/dns/alibaba-cloud-dns-custom-permission-policy-reference-dns)、[Certbot 修改续期配置](https://eff-certbot.readthedocs.io/en/stable/using.html#modifying-the-renewal-configuration-of-existing-certificates)。
