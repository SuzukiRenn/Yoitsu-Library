# 域名与 HTTPS 离线准备

当前采用域名方案，域名实名验证尚在办理中。域名实名验证不等于 ICP 备案通过。服务器仍运行已验收的私有预部署提交 `d585d79825dbf5e27feac12e3abf52821f12fc0d`，本轮未连接服务器、修改网络、申请证书或初始化管理员。

## 已完成的代码

- `BOOKLIST_TRUSTED_PROXY_IPS` 同时用于 Gunicorn 协议判断与应用客户端地址恢复，只接受明确 IP，拒绝通配符、网段和名称。默认空值保留原有私有部署行为。代理覆盖外来转发头，应用只从可信来源接收单个合法客户端地址，随后移除转发头，避免业务层再次使用未验证的地址。
- HTTPS 方案保持 Secure Cookie、同源 CSRF 校验和应用 HTTPS 重定向。代理终止 TLS 后由 Gunicorn 设置请求协议，不让 Django 直接信任任意协议头。
- `BOOKLIST_ICP_RECORD` 默认空，不显示页脚；取得真实网站备案号后配置，公共页面、管理页面和管理登录页显示号码并链接工信部备案查询。域名实名状态不作为备案号。
- 本机生成 Nginx HTTP 验证入口、HTTPS 配置、Compose 叠加文件及状态清单。静态目录独立只读挂载，`.mjs` 明确使用 JavaScript MIME；关闭访问日志，不持久化搜索词及登录请求。

## 本机生成与检查

在 PowerShell 项目目录执行（只读当前提交并写入新的 `.runtime` 目录，不联网）：

```powershell
$release = git rev-parse HEAD
.\.venv\Scripts\python.exe -B scripts/prepare_https.py --domain sharedbooklist.xyz --release $release
.\.venv\Scripts\python.exe -B scripts/test_https.py
```

准备目录中的 `compose.https.json` 需与 `deploy/compose.yaml` 合并，不能独立运行。生成配置默认只映射 `127.0.0.1:8080` 和 `127.0.0.1:8443`，应用仍无端口映射。证书工具在非默认 profile 中，默认命令仅输出版本。生成器不执行 Docker、SSH 或证书命令，也不确认域名已注册、SHA 已发布或前提已满足。

当前默认代理地址为独立内部网络 `172.30.29.0/28` 中的 `172.30.29.2`。这是候选配置，实际执行前必须检查服务器已有路由、Docker 网络和 VPN，冲突时通过 `--subnet`、`--proxy-ip` 一起调整；不得简单信任整个 Docker 网段。代理同时连接独立入口网络，应用、备份和调度保留内部网络。

镜像使用固定版本及多架构索引摘要，执行平台固定为 Linux amd64：

- [Nginx 官方镜像 1.30.4-alpine](https://hub.docker.com/_/nginx)：`sha256:dc5069ad14f19660b141b21236140b91656bf89bbc3e2417c70ae650cd66104c`。
- [Certbot 官方镜像 v5.8.0](https://hub.docker.com/r/certbot/certbot)：`sha256:f70ad0adbb7e117f0fe42a63c553f28ea451edabc0148757b6efcd9735acaa20`。

版本与摘要于本轮准备时核对。首次安装和以后升级仍需核对上游公告，并在隔离环境完成验收，不盲目切换 `latest`。

## 服务器验收时需要完成的工作

以下是后续步骤，尚未执行；生成配置不能直接视为已上线方案。

1. 确认域名归属、实名及备案条件；在备案办理渠道提交材料，按接入商流程安排解析。实际公开开放前确认网站备案通过并适用于本次接入。
2. 用新提交构建应用和隔离测试镜像，执行 Linux 回归；保留当前数据库、密钥及备份，不把本机验收库放入服务器。
3. 检查候选网段、目录权限和固定代理地址。将运行镜像的 `/app/staticfiles` 导出到版本独立的 `/var/lib/shared-booklist/predeploy/static/<release>`；只能复制静态产物，不复制数据库。Nginx 配置安装至 `/etc/shared-booklist/https/nginx.conf`。
4. 在不开放公网的隔离环境验证 Nginx 配置语法、证书读取权限、代理协议、真实 IP 和 JavaScript MIME。Compose 合并校验不等于 Nginx 或 TLS 验收。
5. 公开验证条件满足后，再部署 HTTP challenge 入口，使用 webroot 方式先验证测试环境、再申请正式域名证书。测试证书与正式证书采用独立名称和目录，测试证书不得安装为业务证书。域名证书无需沿用先前 IP 证书的专用短期配置。
6. 私钥只留服务器私有目录。Nginx 以 UID/GID 10001 读取专门导出的证书目录 `/etc/shared-booklist/https/tls`，目录建议 root:10001、0750，私钥 0640；不把完整 ACME 账户目录挂给代理。证书更新应先校验匹配及有效性，再原子安装并执行 `nginx -t` 和 reload。
7. 配置定时续期和证书更新后的部署步骤，完成 `renew --dry-run`、reload 及有效期监测验收。当前只准备证书工具镜像，尚未安装续期任务，不能据此认为续期已具备。
8. 经确认切换公网 80/443、安全组及固定域名，验证可信 TLS、重定向、静态资源、匿名身份、CSRF、限流、管理员交互初始化和异地恢复。业务回归使用隔离测试库，不写入真实书单。记录切换与回滚步骤，配置回退不覆盖新数据库贡献。

本机已完成 170 项应用测试（含代理、安全 Cookie、同源校验、访客独立限流和条件备案页脚），3 项生成器检查，以及完整离线导入、前端协议和迁移往返验收。Compose 使用客户端检查合并；服务器专用 env 文件在本机检查时用独立空文件替代，不复制真实配置。Nginx Linux 运行、真实证书及自动续期尚未验收。
