# 阶段 1 技术设计

依据总规范 v1.6，D1—D12 全部已确认。本文件的生命周期、限流及协议数值是可配置工程选择，不是补充产品承诺；后续按测试及运行证据调整。阶段 1 不开放采集、推荐、点赞、活动管理或合并写入 API。

## 实现范围与目录

新增 `config/`（Django 配置/路由）、`booklist/`（模型、迁移、基础安全服务/API、管理命令、测试）、`static/`（共享文本规则）、`requirements/`（精确依赖与 wheel 哈希）、根级忽略、配置示例和 README。现有 tests 下的采集原型及历史数据保留。核心逻辑表在一个 app 内分文件维护，先避免跨 app 迁移循环；各业务服务后续独立模块扩展。

只用 Django 核心及标准库；独立 Python 3.14 环境，不从旧 .venv 继承。管理员是独立模型，使用 Django 密码哈希工具；不开放内建任意表编辑后台。管理员与匿名分别使用独立 Cookie 和数据库 token 哈希，数据库不保存原始 token。没有普通用户注册或公开身份字段。

## 请求与安全协议

- 基础路径 `/api/v1/`，JSON 对象请求；错误统一 `{error: {code, message}}`。请求体上限 32 KiB，分页默认 20、最多 100。时间为 aware UTC，输出 ISO 8601 毫秒加 Z；页面/管理员输入换算 Asia/Shanghai。活动区间左闭右开。
- 理由按固定 ECMAScript WhiteSpace/LineTerminator 集合去首尾空白，CRLF 与 CR 归一 LF，再计 Unicode 码点；拒绝非配对代理字符。书名等文本同样标准化并按确认上限校验，原始来源由独立来源诊断结构保存，超限不截断。Python 和 JavaScript 共享黄金样例测试。
- 匿名 Cookie 365 天，成功身份请求续期；原始 token 由 `secrets.token_urlsafe(32)` 产生，库内 SHA-256，重置撤销旧 token、不迁移或删除旧贡献。管理员会话绝对 12 小时，到期重新登录；改密/停用通过账号 session_version 使全部旧会话失效，同时删除对应会话行。
- Cookie HttpOnly、SameSite=Lax，生产 Secure，两个 Cookie 不共享身份。所有写入（包括首次签发、登录及退出）受 Django CSRF 中间件保护；先 GET `/api/v1/csrf/` 再带 CSRF 头提交。同源部署，不信任客户端提交的管理员或匿名身份 ID，不信任任意代理转发 IP。
- 基础数据库限流：匿名签发/重置每地址每小时 20 次、管理员登录每地址每 15 分钟 10 次、管理写入每账号每分钟 60 次；后续业务入口按范围追加。限流 key 为服务端秘密派生的 HMAC，库内不保存原 IP。应用多进程共享计数；运维应定期清理到期桶。限流计数与业务事务分离，业务失败不会丢失失败尝试计数。
- 生产缺密钥/允许主机/外部持久目录配置时失败停止；开发必须显式启用开发模式。密钥不写入前端、日志、审计或 Git。

## 数据模型与约束方案

全部外键采用 PROTECT，避免贡献因作品、活动、匿名身份或管理员删除级联丢失。作品非空来源 ID 唯一但标题不唯一；公开审核与来源身份独立；四个展示字段具有独立覆盖标记，允许作者/简介/封面主动空，最终书名必须非空。来源获取状态和原值独立保存。

标准标签、来源身份映射、来源关联抑制、作品级禁止分开建模。work_tags 对用户、管理员、来源分别设置操作者检查和有效唯一约束，不能用一个带 NULL 操作者的唯一键替代。

`SourceFieldState` 保存原值、字段诊断及可空 `collection_complete`，成功且完整的标签集合才能撤销旧来源标签；未取得完整性证据时不能将空数组当作来源清空。TagSource 使用带命名空间的来源 key（如 `wenku8:id:<ID>`，无 ID 时使用经过确认的名称 key）映射主标签，不以同名自动合并。

推荐与赞均区分公共和活动范围，检查 activity/activity_work 的空值组合；公共与活动分别建有效唯一约束。数据库触发器校验活动快照所属作品/活动及未归档状态。活动快照保留历史，重复有效记录唯一；后续合并须先将贡献迁往目标快照再归档旧快照，不依赖不一致的中间提交。

活动计划起止、终态、结束/取消时间有检查；时段冲突保护将在阶段 5 事务服务落实，阶段 1 不开放活动安排接口。自动转换有独立事件表，业务生效时间与处理时间分开。历史修正与审计关联，资料快照不跟来源同步。

推荐文本隐藏状态与资格失效时间分开，文本隐藏不参与有效推荐唯一性与人数判定；活动空理由有效，公共有效理由非空。合并操作、逐项快照、依赖关系预留，不实现合并/撤销业务。

请求幂等记录绑定匿名身份、操作范围、key 哈希和规范化请求摘要；默认保留 24 小时。后续业务必须在同一短事务内登记结果、执行写入，同 key 异内容返回冲突。阶段 1 建结构与服务级测试，不把它当作尚未开放业务接口的完成证据。

## 事务、历史变更与审计

SQLite 配置外键、短 IMMEDIATE 写事务、5 秒锁超时，不使用 ATOMIC_REQUESTS，不在事务内联网。生产 SQLite 版本需要含已知 WAL 修复；本地开发库也检查实际链接引擎，而不是系统 sqlite CLI。

数据库触发器为所有可变业务表产生追加式 ChangeEvent（全局递增序列、表名、实体 ID、当前作品归属、insert/update/delete、处理时间）。序列就是版本证据；物理删除仍留墓碑事件，不保存理由正文或 token。这样 QuerySet.update、bulk 与原生 SQL 不会绕过检测。安全撤销的逐项前后快照在未来合并事务保存；遇新事件先停止自动撤销，不凭时间猜归属。触发器本身不等于合并/撤销已实现。

管理员修改和 AdminAuditLog 同事务；审计与 ChangeEvent 禁止普通 SQL UPDATE/DELETE（SQLite 触发器），无公开查询入口。审计采用允许字段的显式构造，不序列化请求全文，理由治理仅在明确操作时记录原文。系统转换不伪造管理员 ID。

最后管理员保护使用 IMMEDIATE 事务加数据库触发器覆盖并发停用及删除；创建/改密均使用 Django 密码验证器及哈希，初始化命令只允许创建第一个管理员且可重复执行。后续管理员由已登录有效管理员创建，HTTP 不提供公开注册或管理员 ID 冒用能力。

迁移 `0003` 补全来源集合完整性和实际活动时间约束。SQLite 表重建会移除表上触发器，故涉及重建的迁移在同一 schema 事务内先撤下旧触发器、改表、重新安装；正反迁移都维护完整触发器集合。未来不能只生成 ORM 迁移而忽略这一点。服务器密码遗失通过本地恢复命令审计重置并撤销旧会话，不开公网重置入口，不启用被停用账号。
