# 共享书单课设升级设计与验收基线

适用分支为 `codex/course-project-upgrade`，身份版基线为 `76c0363101bda63d2cdac7ae7d7d025d442daf70`，目标域名为 `course.sharedbooklist.xyz`。本文记录本次设计和验收条件。测试实绩、最终提交与上线结果以验收记录为准。

## 范围与角色

继续使用 Django、SQLite、服务端模板和原生 JavaScript。书目资料、权限、作品公开状态以及推荐与点赞的统计规则沿用身份版。访客可浏览公开内容，登录读者可创作与参与，策展成员可编辑草稿，负责人可发布书单，管理员负责内容治理。阅读路线是作品详情页的一项读者内容。

## 功能与数据流

| 入口 | 整体设计 | 异常处理 |
| --- | --- | --- |
| AI找书 | DeepSeek 将查询转成有限的检索条件，服务端校验后在可见轻小说目录中查找。智能查找、关键词查找、调整条件和降级检索均可匹配展示书名、有效别名、展示作者、展示简介及有效标签。未推荐的可见目录作品可打开详情，公共书架仍沿用其有效推荐范围。模型使用服务端凭据，模型输出不直接决定作品 ID、引用原文或可见性。 | 部分条件命中时仅列有依据的部分。资料未提及某一特征，不能推定作品不含该特征。无匹配、超时、无密钥、无效响应或超额时给出下一步可用入口。 |
| 协作书单 | 负责人建立草稿，添加协作者。成员提名、调整理由与次序，负责人审核后发布。发布生成不可变的内容快照；读者可查看相邻版本的新增、移除与排序变化。 | 草稿保存和发布校验角色及版本号；过期写入应提示冲突。公开读取仍要遵循作品当前可见性，历史版本不得重新公开已受限元数据。 |
| 作品详情的阅读路线 | 登录读者自由写建议，使用已有的斜杠选书与剧透折叠。不同读者各自发表观点，作者可更改或撤回自己的内容。路线使用独立内容记录，不改变该书的推荐、点赞计数。 | 未授权编辑被拒绝。目标作品失效后不能通过引用访问受限详情；正文按用户内容的治理规则处理。无需系列全库标注。 |
| 找书互助 | 登录读者发布线索并可补充；他人提名候选作品并说明依据；发起人确认或撤销采纳。其他读者可按线索检索已解决的求助。 | 同一求助不能重复计入同一候选作品；同一时刻最多一个被采纳答案。撤销使求助重新开放，原有线索和候选仍可查。 |

## 开发与发布边界

开发、验收和新站各用独立数据目录与配置。检索数据取自新站自己有权展示的书目；演示使用可分发书目或合成案例。五千余条候选书目不能直接当作公共书架有效书目数，具体规模以新站导入和公开范围为准。现网数据库、账号、消息和推荐行为不作为测试夹具。默认无需外部向量数据库或用户建库。

DeepSeek 模型名、密钥和调用限额通过服务端配置管理，固定响应测试不产生外部调用；只有真实 API 检查可证明服务联通。调用预算以请求数、输入输出长度及并发限制落实并报告实测。公共查询时须考虑重复请求和超额；不向模型发送用户档案或数据库内容。

新站采用独立应用服务、静态目录、SQLite 数据、应用密钥与备份目标。只为已确认子域名新增入口；TLS、Cookie、静态和上传资源均验证站点归属。上线前记录现网关键入口的状态与跳转，验证新增域名配置，准备只撤回新站的操作。新站账户、找回密码或邮件验证若依赖外部配置，需在公网验收中明确可用的真实流程。

## 独立验收用例

| 编号 | 从真实入口操作 | 可观察的验收条件 |
| --- | --- | --- |
| S1 | 在 AI找书输入组合偏好、修改其中一个条件 | 可见候选和原文可核对，部分命中明确。未推荐的可见作品可以搜到并打开，隐藏、合并、待审及退役作品不会出现在结果中。 |
| S2 | 分别检索无匹配需求，模拟模型返回空白、超时、格式错、预算耗尽 | 不展示虚构书名或依据；输入保留，用户能继续普通搜索。测试记录区分真实和模拟调用。 |
| S3 | 用预先标注的固定题集，分别在普通搜索和自然语言入口找书 | 记录题数、两方法输入、前三结果和命中分母；无答案题单列，避免用命中率掩盖猜测。 |
| C1 | 两个独立会话分别以负责人和成员编辑、发布同一书单；访客查看 | 成员可参与，只有负责人能发布。发布前访客看不到草稿，发布后才有对应版本。 |
| C2 | 两个编辑会话从同一版本保存不同修改；发布第二版，查看第一版 | 迟到写入不覆盖先前修改，可识别冲突；旧版次序和理由可核对，差异与实际改动相符。 |
| R1 | 从作品详情写路线，斜杠引用他书、标记剧透；第二位读者也发表路线 | 引用链接可用，剧透默认折叠。作者可以修改、撤回自己的路线，其他账户不能代改；推荐统计不因路线增减而改变。 |
| H1 | 发起求助、补充线索；两人尝试提交相同候选，再由发起人采纳、搜索和撤销 | 无重复候选，只有发起人有权采纳；最多一个有效答案，撤销后可继续求助。 |
| D1 | 从空白独立数据目录迁移、启动，运行既有回归，再用窄屏从首页操作上述四项 | 记录运行条件、通过/跳过/失败数、关键入口到达情况及实际阻塞。 |
| D2 | 核对 GitHub 远端分支，公网访问 course 子域并复核原站 | 远端提交与验收提交一致，TLS 和内容对应新站，静态与账户会话隔离，原站状态与上线前对照一致。 |

本地功能通过、真实模型联通、GitHub 推送和公网新站通过分别记录。每项附提交、环境、实际观察结果和未验证条件。
