# 公网 IP 与 HTTPS 上线准备

用户选择先按公网 IP + HTTPS 方案准备，不把购买域名作为技术前提。当前服务器仍运行已验收的私有预部署版本，未开放公网 Web 端口，尚未签发 IP 证书或初始化真实管理员。本文件是准备方案，不代表上线完成。

## 公开访问的前提

先确认服务器地域和该网站的备案状态。按[阿里云通用网站备案说明](https://help.aliyun.com/zh/icp-filing/basic-icp-service/product-overview/icp-filing-requirements-for-a-regular-website)，中国内地服务器通过 IP 提供网站也需要 ICP 备案，阿里云代备案系统目前只支持域名备案，不支持 IP 备案。IP 证书可签发与网站可以对外开放是两个独立问题。

如果当前网站尚未备案，先确定可行的备案与部署路径，保持私有服务；不通过修改端口、使用 HTTPS 或隐藏登录入口把未备案网站对外开放。确认已有备案时，也须核实备案主体、网站和接入信息适用于这次发布。

## 证书和自动续期

[Let's Encrypt 已提供公开信任的 IP 证书](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)，有效期 160 小时，必须使用短期证书配置。按[官方 Certbot 指引](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)，采用支持 IP webroot 验证的 Certbot 5.4 或更新版本，指定 `--ip-address` 和 `shortlived` profile；先在 staging 完成验证，再申请正式证书。

webroot 验证需要公网 TCP 80 能访问指定的 ACME challenge 文件。HTTP 只处理验证请求及向固定 IP 的 HTTPS 跳转，不处理业务写入。证书签发后才能启用业务 HTTPS。签发工具不能被视为已自动完成 Nginx 证书安装；必须配置定期续期、更新后的配置检查与服务 reload，并验证续期演练及到期监测。证书私钥和 ACME 账户材料仅留在服务器私有目录。

## 应用与代理需要联动的部分

1. 配置明确的公网 IP 主机白名单，保留生产 HTTPS 重定向及 Secure Cookie；不使用 `ALLOWED_HOSTS=*`，不为 IP 访问降级 Cookie 设置。
2. 用反向代理终止 TLS，并提供只读静态文件，确保 `.mjs` 的 JavaScript MIME 类型正确。Gunicorn 不映射公网端口。
3. 代理覆盖传入的协议和客户端地址转发头，应用只信任指定代理来源。当前 Gunicorn 仅信任回环地址；若代理通过 Docker 网络连接，必须联动配置可信代理地址，否则会发生 HTTPS 重定向循环。不能直接改为信任所有来源。
4. 现有限流读取 `REMOTE_ADDR`。代理部署时须恢复经过校验的真实客户端地址，防止全部群友共用一个代理 IP 的限流额度，也防止请求者用伪造转发头绕过限流。
5. 使用现有生产配置与持久化数据库，不重置随机密钥，不导入开发库或示例作品。每次配置变更保留回滚材料；不通过回滚数据库覆盖新贡献。

## 发布验收顺序

确认公开访问前提及具体方案后，再固定工具版本、准备并验证代理配置，执行服务器端配置检查。签发与续期演练通过、TLS 证书匹配实际 IP、静态资源和受信转发链正确后，验收公网 HTTPS 与匿名身份流程，再交互初始化真实管理员。管理员密码只在终端输入，不进入聊天、脚本参数或日志。

公开前还需完成原预部署手册约定的异地备份及恢复安排。功能写入回归继续使用隔离测试库，不向真实书单写入合成书名、推荐或测试活动。实际公开访问、管理员初始化、证书签发、续期及恢复结果分别留存验收记录，不能用私有 HTTP 健康检查代替公网 TLS 验收。

服务器地址、地域确认对话、备案材料、联系方式和实际执行日志不写入此公开仓库。备案材料仅在云厂商或主管部门的正式办理渠道提交。
