## 读者使用流程

使用新迁移的临时 SQLite 数据库、两名合成读者和一名访客，通过 Django HTTP 客户端启用 CSRF 校验。29 项业务断言通过。

| 功能 | 实际观察 |
| --- | --- |
| 自然语言找书 | 固定模型意图能检索到测试作品，返回与展示简介一致的原文。另一部有相同描述但未进入公共书架的作品不出现在结果中。未配置模型密钥时仍可按书名检索。 |
| 协作书单 | 负责人通过读者编号邀请成员。两人基于同一草稿版本并发修改，收到一个成功跳转和一个 HTTP 409 冲突。成员发布返回 403，负责人可以发布。第二版加入新书后，第一版仍保留原内容；隐藏作品后旧版不再显示该书资料。 |
| 阅读路线 | 作者可发表、修改及撤回；另一名读者无法撤回他人的路线。撤回未改变作品的有效公共推荐。窄屏浏览器中实际输入斜杠、选中候选作品并标记剧透，返回详情后能展开文字并看到引用链接。 |
| 找书互助 | 发起人补充线索后，其他读者可提交候选。同一求助重复提名被拒绝；仅发起人可采纳。可按补充线索查到已解决的求助，撤销后退出已解决结果。 |

桌面 Chrome 以 **390 × 844 CSS 像素**模拟触屏，从首页完成本地找书、作品路线、协作提名和发布求助。四个页面均无横向溢出。普通动效下快速导航有原生过渡中止通知；各项操作均完成。减少动效、等待页面加载完成后重跑，四项均通过，页面无未捕获异常。没有使用实体手机。

## 检索评测与回归

- 演示题集使用 4 本合成作品，共 5 道题，其中 4 道有答案。以正确书目进入前三条为命中，整句普通检索为 1/4，人工选择关键词与标签为 4/4，固定意图检索为 4/4。另 1 道无匹配题单列。该测试使用固定模型响应，真实 DeepSeek 理解质量、延迟和费用待实调。
- 另建 5,000 本有效公共作品的合成 SQLite 书架，其中 25 本包含目标线索。在本机连续 3 次执行本地匹配与排序，耗时分别为 0.469、0.498、0.472 秒，每次返回的前 15 条均含对应原文。测量未包含模型网络请求、页面渲染或并发用户，不能作为生产响应时间。

## 容器与公网交接

使用 Docker Desktop Linux 引擎从 Git 源码分别构建应用与 Nginx 镜像。验收过程中发现并修复了两个实际运行问题：网关固定地址被动态分配占用，以及 SQLite WAL 冷启动时备份容器无法创建旁文件。最终从新的空数据卷启动，迁移到 `0023_course_features`。应用、课设网关、调度和备份服务均已运行，Nginx 配置校验通过，调度输出 `scheduler_ok`。

1. 宿主回环入口的健康页、首页、自然语言找书、协作书单、找书互助及前端 JS 均返回 HTTP 200。容器边缘网络上的受信代理访问健康页也返回 200。
2. 使用仓库的公网虚拟主机示例、仅在本机生成的测试证书及隔离测试代理，实际校验课设域名并通过 TLS 1.3 请求找书页，返回 HTTP 200 且页面内容匹配。实际 DNS、正式证书与服务器仍由部署后确认。
3. 全新数据卷冷启动的首份自动备份回执 `status=verified`、`backup.restore_drill=true`。应用在线写入一条合成书目后，再从备份容器生成并校验副本，在副本中读取到该书目恰好一条。
4. 本轮验收用的 Compose 应用、模拟公网代理及临时网络已停止和撤回。本地开发演示单独运行在回环地址。

本次未配置真实 DeepSeek API 密钥。新站仅需服务端为 `COURSE_DEEPSEEK_KEY` 配置课设专用密钥，首版直接使用新站可见书架的标签和简介。正式接入后需从自然语言入口查一次有明确证据的作品，并核对真实返回、用量和回退状态。

公网 DNS 和服务器接入由用户负责。交付时 `course.sharedbooklist.xyz` 尚未完成公网验收。接入前只读观察到身份站首页 HTTPS 200，原域名以 302 跳转到身份站，TLS 校验通过。上线时应再次检查新站子域的证书、入口及旧站的同一组行为。
