# 阶段 2：离线小样本导入设计

依据总规范 v1.6。本轮只处理已保存的 4151、3219、2951 三份详情元数据，不新访问文库8、不下载封面或正文。采集路线的服务器验证仍未完成，因此本轮仅交付阶段 2 的离线导入部分，不将历史 HTML 成功称作新在线采集成功。

## 复用与修改范围

保留原 `tests/wenku8_pages/parse_wenku8_pages.py` 和其详情解析依赖不变；在 `integrations/wenku8/` 新增适配器。旧解析器把缺字段一律视为必要字段错误，新适配器只对可信详情 ID/标准标题执行身份硬校验，对其他字段补充 DOM 存在性、明确空值与集合完整性诊断。只接受详情，不导入候选的截断标题。

新增 `booklist/importing.py`（事务同步）、管理员字段覆盖与标签抑制的服务、离线管理命令、ImportBatch/ImportItem/ImportAttempt 队列与结果记录、必要迁移、独立样本/测试及解析依赖锁。旧解析代码本身也纳入明确的 Git 文件清单，避免私有仓库发布后缺少运行依赖；历史完整页面/浏览器资料不因此整批上传。

## 输入、状态与断点

版本化 JSON manifest 每批最多 20 项，只允许本地文件；每项有唯一 key、预期 book_id、规范详情 URL 与 manifest 目录内相对 HTML 路径。建立批次时绑定 manifest 内容 SHA-256、每个输入文件 SHA-256 及适配器/复用解析代码指纹。检查文件大小、编码、路径范围和详情身份，不执行网页脚本，不打开 URL。暂存结果只保存元数据 envelope，不保存账号 HTML、Cookie 或请求头。

解析在事务外，每项写入在独立短 IMMEDIATE 事务：同步作品/来源字段/标签、记录本项 attempt、更新结果状态和系统审计，整体提交或回滚。一项失败保留明确原因并继续下一项；已提交项目在崩溃后保留，未提交项目可由原批次恢复。不用一个长事务包整批。

项目状态 pending/imported/partial/failed；partial 表示身份导入成功但可选字段有缺失/错误，必须保留警告，不能将字段错误报成全字段成功。`--max-items` 可限制本次处理项数；`--resume` 只处理 pending，`--retry-failed` 明确重试 failed。恢复时拒绝 manifest、已有输入或解析指纹变化；修正样本内容后建立新批次，不混入原批次。相同样本的新批次可重新同步，但不得重复创建作品或标签，也不为没有变化的业务行产生无意义更新。

## 字段与身份

可信 ID、详情 URL 和详情主区域 ID 必须一致，标题须为详情标准标题且通过 300 码点限制；身份失败隔离整项，不自动补绑未知作品或合并历史。已占用来源 ID 的同步只更新原正式记录；遇来源记录被合并等异常则停止该项，不新建替身。

每字段独立保存 value/empty/not_fetched/parse_error/invalid、raw_value 和集合完整性。只有 value 或有明确来源证据的 empty 能同步；标题不得清空。获取失败不覆盖旧来源值；保留原始来源值及校验结果，不静默截断。已知来源更新时间倒退时停止该项，防止旧样本覆盖较新资料；未知时间不伪造新鲜度保证。

本轮适配器按已保存元数据区域版式验证显式文档结束与 HTML 解析诊断；不能用 lxml 自动补齐的结束节点证明标签集合完整。截断/恢复有错误的文档只保留可信身份，可选字段记解析失败，不清空或覆盖旧数据。作者/分类/状态暂用 300 码点、封面 URL 2048 字符、单项标签集合 200 条作为适配器工程上限，超限保留原值和错误，不阻止身份有效的作品以部分成功导入；这些不是全站实测上限。

作品原始提交标题、public_added_at、隐藏/审核/合并状态、管理员覆盖均不被导入改写。四字段覆盖与来源字段独立；管理员可主动清空作者/简介/封面，恢复同步取消标记。所有管理改变有同事务审计，导入是系统行为，不伪造管理员身份。

## 标签与纠错

现有三份详情标签为纯文本、无原始标签 ID。使用规范化精确名称形成 `wenku8:name:<名称>` 来源 key；有独立可靠 ID 的 envelope 则使用 `wenku8:id:<ID>`。两种身份不靠语义相似自动归并；不同 ID 同名保留独立标签并标记核查。来源名称变化先记录待核查，不覆盖管理员修正的显示名。

导入先解析已确认来源映射及主标签，再同步来源关联。只有标签集合完整成功才能撤销来源已移除的关联；空但有完整证据的集合可以撤销，缺节点/解析失败不能。用户与管理员来源不受来源同步删除影响。TagSource 的既有映射不得被重复导入重建成旧标签。

单条来源纠错保留抑制标记，作品级禁止覆盖全部来源；重复导入均不得绕过。明确解除来源抑制后，后续完整同步才可恢复跟随来源。停用标签不会被导入重新启用，历史关联可保留，但未来公开查询仍须应用停用/禁止规则。标签全面合并/撤销界面仍属后续阶段，不用测试中预设的映射冒充完整合并服务。

## 验证与 GitHub 时点

验证三份真实保存详情、重复导入、字段缺失/明确空/超限/身份冲突、完整/不完整标签集合、原始输入/覆盖/隐藏保留、来源抑制及映射、不同 ID 同名、断点恢复/失败重试/原子回滚、旧材料哈希和阶段 1 回归。异常分支的内存变体明确标为测试注入，不视作线上观察。

阶段 2 离线验收后可接入 GitHub 私有仓库，早于生产部署。届时需要仓库所有者/仓库名和用户本机授权；不收取聊天中的密码或 token。首次推送前审查明确文件清单、依赖锁、去敏样本和忽略规则。当前只有本地 Git，远程仓库/授权不阻塞离线实现；服务器以后使用独立只读仓库凭据。
